# Authentication — testing

> **Status:** Accepted (living document)
> **Last updated:** 2026-10-21
> **Owner:** maintained by the `docs` agent
> **Feature:** [`ATOM-FEAT-AUTH-001`](specification.md)

What the repository's test suite covers for the authentication feature, and
what it deliberately does not.

This document describes the suite as it exists in the tree. It does not
claim that any run happened. What must pass before a change is considered
complete is stated in
[`verification-policy.md`](../../testing/verification-policy.md).

## 1. Integration tests — `tests/auth_api.rs`

Every test in this file runs against a real PostgreSQL database. The harness
applies the migrations, registers a unique account per test and calls the
router directly.

| Test | What it proves |
| ---- | -------------- |
| `registration_returns_a_token_pair_and_a_safe_user` | `POST /auth/register` returns `201`, a token pair, the user's own record, `token_type` `Bearer`, a positive `expires_in`, and **no** `password_hash` in the body. |
| `registration_normalises_the_email_address` | An address submitted in upper case is stored and returned lower-cased. |
| `duplicate_registration_is_a_conflict` | Registering the same address twice returns `409` with the code `conflict`. |
| `a_weak_password_is_rejected_with_field_details` | A short password returns `422` with the code `validation_failed` and a `details` array. |
| `login_succeeds_with_the_right_password` | `POST /auth/login` returns `200`, the same user id and an access token. |
| `login_fails_with_a_generic_message` | A wrong password returns `401` with the code `unauthorized`, and the message does not say which credential was wrong. |
| `an_unknown_email_produces_the_same_failure_as_a_wrong_password` | An unknown address returns `401` with the same code as a wrong password. |
| `refresh_rotates_the_token_pair` | `POST /auth/refresh` returns `200` and a **different** refresh token. |
| `reusing_a_rotated_refresh_token_revokes_every_session` | Presenting a rotated token returns `401`, and afterwards the rotated token is also rejected — every session of the user was revoked. |
| `logout_revokes_the_session` | `POST /auth/logout` returns `204`, and the revoked refresh token is afterwards rejected by `POST /auth/refresh`. |
| `protected_routes_reject_missing_and_invalid_credentials` | `GET /auth/me` without a token and with a garbage token both return `401`; `GET /notes` without a token returns `401`. |
| `the_current_user_endpoint_returns_the_caller` | `GET /auth/me` returns the caller's `id` and `email`, and **no** `password_hash`. |
| `an_account_cannot_log_out_another_accounts_session` | Logging out with another account's refresh token returns `403`, and the victim's session still works afterwards. |
| `the_authentication_endpoints_are_rate_limited` | Driving the login endpoint past the limit returns `429` with the code `rate_limited`. The test uses a state with a limit of two requests. |
| `a_disabled_account_cannot_authenticate` | Deactivating the account makes login, `/auth/me` and refresh return `403`. |
| `an_expired_refresh_token_is_rejected` | An expired session returns `401` with a message that says the token expired. |
| `an_expired_access_token_is_rejected` | A token whose `exp` is an hour old returns `401`. |
| `revoking_every_session_invalidates_the_refresh_tokens` | Revoking every session of the user makes every refresh token of that user unusable. |
| `a_concurrent_refresh_of_the_same_token_succeeds_only_once` | Two concurrent exchanges of the same refresh token produce exactly one `200` and one `401`: the rotation is atomic. |
| `logout_with_an_unknown_refresh_token_is_accepted` | Logging out with a token that never existed returns `204`: logout is idempotent. |
| `a_malformed_json_body_is_a_bad_request` | A body that is not JSON returns `400` with the code `bad_request`. |
| `an_unknown_query_parameter_value_is_a_bad_request` | An unknown enum value in a query string returns `400`. |
| `an_oversized_body_is_refused` | A body over the configured limit returns `413` with the code `payload_too_large`. |
| `an_unknown_route_returns_the_error_envelope` | An unmatched route returns `404` with the standard envelope, not an empty body. |
| `the_request_id_is_echoed_on_the_response` | A correlation id supplied by the client is echoed on the response. |
| `a_generated_request_id_is_propagated_to_the_response` | A correlation id generated by the server is echoed on the response. |

## 3. Deliberately not covered

| Gap | Why |
| --- | --- |
| **The per-user session revocation over HTTP.** `AuthService::revoke_all_sessions` has no endpoint, so it is covered at the service level by `revoking_every_session_invalidates_the_refresh_tokens` rather than over HTTP. The product question of whether such an endpoint should exist is `Q-08` in [`open-questions.md`](../../engineering/open-questions.md). |
| **The timing of the generic login failure.** The unknown-address path performs a real Argon2 verification against a dummy hash with the configured cost parameters, but a test cannot assert the absence of a timing difference without a statistical method that would be flaky in CI. |
| **The rate limiter's behaviour across processes.** The limiter is per process. A multi-instance deployment needs edge rate limiting; see `KI-001` in [`known-issues.md`](../../engineering/known-issues.md). |
| **The refresh-token absolute lifetime.** A test would have to wait out the lifetime or move the clock. The expiry check itself is covered by `an_expired_refresh_token_is_rejected`, which moves the row's `expires_at` instead. |
| **A password change.** There is no such endpoint in Phase 1. |
| **Multi-factor authentication.** Out of scope. |
## 4. Conventions for a new test

- Integration tests live in `tests/`, one file per feature area, and use the
  helpers in `tests/common/mod.rs`.
- A new authentication endpoint needs a success case, an unauthenticated
  case and a cross-account case, as required by
  [`CONTRIBUTING.md`](../../../CONTRIBUTING.md) §3.
- Use `register_user` and `unique_email` rather than hard-coded
  credentials; the suite shares one database.
- A security regression needs a test that fails without the fix.
